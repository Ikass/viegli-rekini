## 2026-10-16 — Dashboard redesign: "New invoice" as the dominant action
Goal: Rework the post-login dashboard so creating an invoice is the dominant action (≤3 guided actions), consolidate the three stat cards into one summary card, and apply the card/badge polish.
What happened: Rewrote `dashboards/show.html.erb` (page-header row with title + New invoice, single summary card, "View all →" in the Recent-activity header). Added a `status` filter to `InvoicesController#index` (whitelist draft/sent/paid/void/overdue) with a single-group filtered view + `_table` partial. Moved dashboard strings to i18n incl. `overdue_count.one/other`. Deleted `kpi.css` + `alert-banner.css`; added `blocks/dashboard.css`. Lowered card shadow to `--shadow-xs` @ 5% and card radius to a new `--radius-card` token. Realigned the global heading scale: `h1` `--step-3`, `h2` `--step-2`, `h3` `--step-1`, `h4`+ `--step-0`. Reduced default `.button` one step (`--step-0`→`--step--1`, `--space-xs/--space-m`→`--space-2xs/--space-s`).
Decision: Overdue row links to `invoices_path(status: "overdue")` via a real filter (not a fake link). App title shrunk by reusing existing `--step-3` (no new token), applied globally. Card shadow made global via existing `--shadow-xs` (alpha 10% → 5%). Trade-off: the filtered invoice list needed a separate single-group render path because the index groups by *persisted* status.
Lesson: `overdue` is derived (sent + `due_on` in the past), not a persisted enum — so the filter resolves through `Invoice.overdue` and the filtered view can't reuse the grouped-by-status loop. The button/heading scales are all fluid (Utopia `clamp()`), so "one step down" = next smaller `--step-*`/`--space-*` token.
Next: Reconsider the fluid typography scale itself (stretch between 375px and 1400px may be too aggressive for app chrome vs marketing). Button scale settled: flat two-tier (`xs` = step--2, default = step--1); `sm`/`lg` tiers removed.
