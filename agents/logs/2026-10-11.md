## 2026-10-11 — VAT rounding fix (per-category, single Ruby source)
Goal: Make VAT/total math match EN 16931 (per-category rounding) and kill the SQL-float drift.
What happened: Replaced `Invoice`'s SQL `SUM`/`ROUND` with Ruby; added `Invoice#vat_breakdown` (per `[category, rate]`, VAT rounded once); `LineItem#subtotal` now rounds half-up instead of truncating; `UblInvoiceBuilder` + `_document.html.erb` read from `Invoice`; moved `TAX_CATEGORY_MAP` into `InvoiceCodes`; added a shared `MoneyRounding` concern. 5 new tests (incl. the epsilon case: 3×1c @21% → VAT 1c, not 0c). 155 unit + 4 system green; RuboCop + Brakeman clean.
Decision: Minimal scope (no `MoneyAmount` VO yet) — consolidation + rounding only, per Q&A. Trade-off: `invoice.total` now loads line items in Ruby (accepted N+1) instead of a DB `SUM`.
Lesson: Moving totals from SQL `SUM` to Ruby exposed the unsaved-line-item path (the invalid-form render) — `LineItem#subtotal`/`vat_amount` must guard nil or the new/edit form 500s on failed validation.
Next: `fix/invoice-numbering` (counter table, numbers at send); README rewrite; Litestream backups.

## 2026-10-11 — Invoice numbering fix (counter table, number-at-send)
Goal: Replace pluck+max numbering with a dedicated counter table; assign numbers at send so drafts never burn a number.
What happened: Added `invoice_sequences` (account + scope) with an atomic `INSERT … ON CONFLICT DO UPDATE … RETURNING`; `InvoiceSender` allocates inside the invoice transaction; `invoice_number` now nullable with a `unless: :draft?` presence validation; draft UI shows "Draft"; seeds allocate for non-drafts; migration backfills one sequence per account. 7 new tests (sequence independence/formatting/digit-prefix, send-time allocation, no-number-consumed-on-fail). 162 unit + 4 system green; RuboCop + Brakeman clean.
Decision: Keep prefix/padding on Account (not per-sequence) and add `scope` now — matches the recipe shape without the account-form churn. Trade-off: allocation lives in `InvoiceSender` rather than the model, coupling the number to the send transition.
Lesson: Rails' `select_value`/`select_all` mishandle an UPSERT's `RETURNING` (return the stale value, don't increment); `exec_query` works. Verify raw-SQL-vs-Rails adapter behavior before assuming a query returns what SQLite returns.
Next: README rewrite; Litestream backups; optional `MoneyAmount` VO.
