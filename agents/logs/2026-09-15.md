## 2026-09-15 — Cross-tenant FK audit + docs consolidation
Goal: Audit cross-tenant foreign-key handling (the `client_id` hole) and consolidate the agent docs tree.
What happened: Added `Invoice#client_belongs_to_account` + `InvoicesController#resolve_client`, removed `client_id` from permitted params; negative cross-tenant tests for clients/products/invoices (show/create/update)/line_items. Switched sessions/passwords/registrations to `params.expect` + a registration rate limit. Docs: new `agents/docs/index.md`, recipes for invoice-number-sequences and money-calculations, refreshed AGENTS/ARCHITECTURE/README/tenancy, moved `agents/specs/` under `agents/docs/specs/`. 133 tests + rubocop green.
Decision: Enforce the FK at both the controller (resolve through `Current.user.account`) and the model (validation) — defense in depth; trade-off: two enforcement points to keep in sync.
Lesson: A `<option>` list scoped to the account is not authorization — a crafted request can post any `client_id`; and `params.expect` takes bare symbols for top-level params (`params.expect(:email_address, :password)`).
